# 1. 项目定位

本项目是一个：

**个人资产风险管理系统**

而不是：

-   普通记账软件；
-   基金/股票交易软件；
-   自动投资顾问；
-   自动化账户管理工具。

核心目标：

帮助用户管理：

1.  钱当前在哪里；
2.  钱当前承担什么风险；
3.  钱未来准备承担什么用途；
4.  当前资产配置是否偏离个人策略；
5.  某项操作会如何影响整体资产结构。

程序负责：

-   记录；
-   分类；
-   计算；
-   模拟；
-   风险提示。

程序不负责：

-   预测市场；
-   自动买卖；
-   替用户决策；
-   访问私人金融账户。

# 2. 核心资产模型

系统必须严格区分三个维度。

------------------------------------------------------------------------

## 2.1 实际资产容器

回答：

> 钱现在实际在哪里？

例如：

-   银行存款；
-   银行卡现金；
-   基金持仓；
-   ETF持仓；
-   股票账户资金；
-   其他资产。

这是现实世界中的资产位置。

------------------------------------------------------------------------

## 2.2 当前风险暴露

回答：

> 这笔钱现在承担什么风险？

例如：

-   现金；
-   固收；
-   国内权益；
-   海外权益；
-   主动策略。

重要规则：

未来用途不能改变当前风险分类。

例如：

某纯债基金中有3万元准备未来用于权益补仓。

那么：

现在仍然属于：

> 固收风险暴露

而不是权益。

------------------------------------------------------------------------

## 2.3 虚拟资金身份

回答：

> 这笔钱未来准备做什么？

例如：

-   日常备用金；
-   自由现金；
-   观察区资金；
-   长期固收核心；
-   权益待投资金；
-   权益补仓储备；
-   主动策略资金；
-   未分配资金。

虚拟资金身份不是实际账户，也不是风险分类。

------------------------------------------------------------------------

# 3. 资金守恒规则

## 3.1 总资产守恒

所有虚拟分配金额不能超过真实资产。

正常情况下：

虚拟资金身份总额 = 实际总资产。

允许临时存在：

-   新录入资产；
-   未分类资金；
-   数据迁移状态。

------------------------------------------------------------------------

## 3.2 容器内部守恒

一个实际资产容器中的虚拟分配不能超过真实余额。

例如：

某纯债：

实际余额：

100000元

可以：

-   固收核心 70000；
-   权益补仓储备 30000。

不能：

-   固收核心 70000；
-   权益补仓储备 40000。

------------------------------------------------------------------------

# 4. 现金身份管理

系统不能只显示：

"现金：150000元"。

必须区分：

例如：

-   日常备用；
-   观察区；
-   权益待投资；
-   主动策略待命；
-   未分配资金。

重点：

> 现金形式不代表资金用途。

------------------------------------------------------------------------

# 5. 快捷资金转换

用户不应该每次手动修改两个账户。

必须支持快捷转换。

包括：

-   自由现金 → 权益待投资；
-   权益减仓 → 低风险资产；
-   权益减仓 → 自由现金；
-   固收 → 权益补仓；
-   观察区 → 实际支出；
-   观察区 → 投资资金；
-   新收入 → 未分配资金。

------------------------------------------------------------------------

## 原子操作要求

一次转换必须：

-   来源减少；
-   目标增加。

两者必须同时成功。

如果失败：

整体回滚。

------------------------------------------------------------------------

# 6. 事件分类

系统必须区分：

## 6.1 真实现金流

改变总资产：

例如：

-   收入；
-   支出；
-   家庭资金转入。

------------------------------------------------------------------------

## 6.2 真实投资操作

改变风险暴露：

例如：

-   买基金；
-   卖基金；
-   ETF交易。

------------------------------------------------------------------------

## 6.3 虚拟身份调整

只改变用途：

例如：

自由现金 → 权益待投资。

不会改变：

-   总资产；
-   实际持仓；
-   当前风险。

------------------------------------------------------------------------

# 7. 在途资金系统

必须支持：

-   待买入；
-   待赎回；
-   待转账；
-   待确认。

规则：

同一笔资金不能重复计算。

例如：

基金赎回后未到账：

不能同时算：

-   基金资产；
-   银行现金。

------------------------------------------------------------------------

# 8. 模拟操作模式

系统需要支持：

不改变真实数据的情况下：

模拟：

-   大额收入；
-   大额支出；
-   调仓；
-   再平衡。

用户确认后才进入真实记录。

------------------------------------------------------------------------

# 9. 仓位状态评估

系统支持：

-   目标仓位；
-   容忍范围；
-   预警边界；
-   硬边界。

状态：

-   正常；
-   接近边界；
-   超出软边界；
-   严重偏离。

显示：

-   当前比例；
-   目标比例；
-   偏离程度；
-   原因。

------------------------------------------------------------------------

# 10. 操作影响评估

重要操作执行前，需要评估：

-   仓位影响；
-   流动性影响；
-   资金身份影响；
-   总资产影响；
-   是否改善或恶化偏离；
-   是否依赖在途资金；
-   是否有后续资金修复。

等级：

-   低；
-   中；
-   高；
-   很高。

必须说明原因。

------------------------------------------------------------------------

# 11. 三状态分析

系统不能只看当前瞬间。

需要计算：

## 当前状态

已经确认的资产。

## 已确认未来状态

包括：

-   在途资金；
-   已确认交易。

## 规划完成状态

包括：

-   已制定调仓计划。

避免连续操作造成误报警。

------------------------------------------------------------------------

# 12. 已覆盖偏离（Covered Deviation）

支持：

当前存在偏离，但已经有：

-   在途资金；
-   已确认操作；
-   足够修复的资金。

则提示：

> 当前偏离已被覆盖，无需立即操作。

------------------------------------------------------------------------

# 13. Strategy Help策略系统

策略说明必须独立于代码。

包括：

## strategy_help.md

给用户阅读：

-   投资纪律；
-   资产配置原则；
-   调仓规则。

------------------------------------------------------------------------

## strategy_rules.yaml

给程序读取：

-   目标仓位；
-   边界；
-   阈值；
-   转换规则。

------------------------------------------------------------------------

# 14. 策略版本管理

策略修改需要保留历史。

例如：

-   Strategy v1.0；
-   Strategy v1.1。

方便未来回顾：

"当时为什么这样设计"。

------------------------------------------------------------------------

# 15. 备份与迁移

必须支持：

-   本地备份；
-   导出；
-   恢复；
-   升级迁移。

历史数据不能因为版本升级丢失。

------------------------------------------------------------------------

# 16. 隐私与联网边界

未来联网只能获取：

-   基金公开信息；
-   股票公开信息；
-   ETF公开信息；
-   市场公开数据。

禁止保存：

-   银行卡信息；
-   支付宝账户信息；
-   券商账户信息；
-   登录信息；
-   Token；
-   Cookie；
-   私人访问路径。

程序永远不能：

-   登录私人账户；
-   自动交易；
-   自动申购赎回。

------------------------------------------------------------------------

# 17. 现金管理伴随项目接口

未来存在另一个：

"完全自用现金管理系统"。

两个项目职责分离。

------------------------------------------------------------------------

## 本项目负责：

投资资产：

-   风险；
-   仓位；
-   投资资金。

------------------------------------------------------------------------

## 伴随项目负责：

生活现金：

-   月度收入；
-   月度支出；
-   消费分类。

------------------------------------------------------------------------

两个项目只共享：

## 完全自用现金

即：

已经确定属于：

-   日常花销；
-   非投资备用。

的数据。

------------------------------------------------------------------------

接口原则：

单向读取。

投资系统输出脱敏接口文件。

现金管理系统读取。

现金系统不能读取：

-   投资仓位；
-   基金；
-   股票；
-   策略。

------------------------------------------------------------------------

# 18. v0.1 不实现

第一版不实现：

-   自动交易；
-   自动投资建议；
-   市场预测；
-   私人账户同步。

------------------------------------------------------------------------

# 19. v0.1 完成标准

第一版完成后，必须可以：

1.  输入资产；
2.  建立资金身份；
3.  快捷转换资金；
4.  模拟收入和支出；
5.  管理在途资金；
6.  计算仓位；
7.  进行风险提醒；
8.  保存历史事件；
9.  验证资金守恒。

------------------------------------------------------------------------

# 20. 最终设计原则

本系统的核心不是预测市场。

而是：

> 让每一笔钱都有明确身份，让每一次操作都知道后果。

系统管理：

-   数学；
-   结构；
-   状态。

用户拥有：

-   最终决策权。
